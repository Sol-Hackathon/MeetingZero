# 테스트 시나리오

첫 화면에 **주제 / 배경 / 목표** 를 그대로 붙여넣으면 됩니다.

각 시나리오에는 참여자 페르소나가 붙어 있습니다. 답변할 때 그 사람인 척 답하면
의견이 실제로 갈려서 2라운드 재질문이 제대로 나옵니다. 모두가 같은 소리를 하면
AI가 "합의됨"으로 정리하고 물어볼 게 없어져서 라운드가 거기서 끝납니다.

> `npm run seed` 로 이 시나리오들을 자동으로 돌려볼 수도 있습니다. 아래 [자동 실행](#자동-실행) 참고.

## 1. 재택근무 정책 축소 — 의견이 가장 크게 갈리는 케이스

**주제**
```
재택근무 정책 조정 (주 2회 → 주 1회) 결정
```

**배경**
```
현재 주 2회 재택이 가능합니다. 경영진에서 "협업 밀도가 떨어진다"며 주 1회로 줄이는 안을 검토 중입니다.

근거로 제시된 것: 작년 대비 스프린트 완료율 12% 하락, 신규 입사자 3개월 이탈률 상승(2명/8명), 사옥 임대료가 좌석 사용률과 무관하게 고정 지출.
반대 근거로 나온 것: 재택 도입 이후 채용 합격률이 올랐고, 지방 거주 인력 2명은 주 1회로 바뀌면 통근이 불가능합니다.

인사팀은 이번 분기 안에 결론을 내고 다음 분기부터 적용하려 합니다. 한번 정하면 최소 1년은 유지합니다.
```

**목표**
```
주 1회로 줄일지, 유지할지, 다른 안으로 갈지 하나로 정하기
```

**라운드 수**: 2

**참여자**

| 이름 | 입장 | 아는 것 / 숨은 사정 |
| --- | --- | --- |
| 정민수 (개발팀장) | 반대 | 스프린트 완료율 하락은 재택이 아니라 QA 인력이 1명 빠진 탓이라고 봄. 데이터를 갖고 있음 |
| 한소영 (인사) | 찬성 | 신규 입사자 이탈 인터뷰를 직접 함. "물어볼 사람이 옆에 없었다"는 답이 반복됨 |
| 김도현 (디자이너, 지방 거주) | 강력 반대 | 주 1회가 되면 이직을 고려해야 함. 아직 아무한테도 말 안 함 |
| 박지훈 (영업) | 중립 | 어차피 외근이 많아 영향이 적음. 다만 회의 잡기가 어려워진 건 사실이라고 느낌 |

## 2. 기술부채 vs 신규 기능 — 우선순위 충돌

**주제**
```
다음 분기 개발 리소스 배분: 결제 모듈 재작성 vs 신규 구독 플랜
```

**배경**
```
결제 모듈은 4년 전 작성됐고 테스트 커버리지가 20%대입니다. 최근 6개월 장애 5건 중 4건이 여기서 났고, 건당 평균 40분 다운타임이 있었습니다. 전면 재작성에는 개발 2명 기준 7주가 걸린다는 추정이 있습니다.

한편 영업에서는 연간 구독 플랜을 요구하고 있습니다. 이미 3개 고객사(합산 ARR 약 1.8억)가 "연간 결제가 안 되면 갱신이 어렵다"고 전달했고, 갱신 시점은 다음 분기 말입니다. 구현에는 4주가 필요하다고 봅니다.

다음 분기에 쓸 수 있는 개발 리소스는 2명 × 10주가 전부입니다. 둘 다 하기에는 3주가 모자랍니다.
```

**목표**
```
다음 분기에 무엇을 먼저 할지, 못 하는 쪽은 어떻게 할지 정하기
```

**라운드 수**: 2

**참여자**

| 이름 | 입장 | 아는 것 / 숨은 사정 |
| --- | --- | --- |
| 이재원 (백엔드) | 재작성 우선 | 장애 대응을 매번 혼자 함. 이대로면 번아웃이라고 생각하지만 말하기 어려움 |
| 최유진 (영업) | 구독 플랜 우선 | 3개 고객사 중 1곳은 이미 경쟁사와 미팅을 했다는 걸 알고 있음 |
| 오세훈 (PM) | 절충 | 결제 모듈 중 장애가 난 건 정산 로직뿐이라는 걸 알고 있음. 부분 재작성이면 3주면 될 수도 |
| 강나래 (QA) | 재작성 우선 | 현재 상태로는 구독 플랜을 얹어도 회귀 테스트가 불가능하다고 봄 |

## 3. 전사 주간회의 폐지 — 이 서비스와 잘 맞는 메타 주제

**주제**
```
매주 월요일 전사 주간회의를 없앨지 결정
```

**배경**
```
매주 월요일 오전 10시에 전 직원 32명이 1시간씩 모입니다. 인당 시간으로 환산하면 주 32시간, 월 128시간입니다.

내용은 팀별 진행 상황 공유 15분, 대표 공지 10분, 나머지는 질의응답입니다. 최근 3개월 설문에서 "이 회의가 내 업무에 도움이 된다"에 긍정 응답이 34%였습니다.

없애자는 쪽은 문서로 대체하자고 합니다. 유지하자는 쪽은 "그나마 다른 팀 소식을 듣는 유일한 자리"라고 합니다. 대표는 "직접 얼굴 보고 방향을 말하는 자리는 필요하다"는 입장입니다.
```

**목표**
```
폐지 / 유지 / 형태 변경 중 하나로 정하고, 없앤다면 무엇으로 대체할지까지 정하기
```

**라운드 수**: 3

**참여자**

| 이름 | 입장 | 아는 것 / 숨은 사정 |
| --- | --- | --- |
| 서지안 (개발) | 폐지 | 월요일 오전이 집중이 가장 잘 되는 시간이라 특히 아깝다고 느낌 |
| 문가영 (마케팅) | 유지 | 이 회의에서 들은 정보로 캠페인 일정을 두 번 조정한 적이 있음 |
| 임태우 (신입, 입사 2개월) | 유지 | 아직 회사 전체가 뭘 하는지 파악하는 데 이 자리가 유일한 통로 |
| 백승현 (재무) | 형태 변경 | 공지 부분만 필요하고 질의응답은 대부분 특정 두 팀 사이 대화라고 관찰함 |

## 4. 가격 정책 변경 — 숫자가 있어 판단이 갈리는 케이스

**주제**
```
무료 플랜 사용량 한도 축소 여부
```

**배경**
```
무료 플랜은 월 1만 건 API 호출을 제공합니다. 이를 3천 건으로 줄이는 안이 나왔습니다.

현황: 전체 사용자 8,400명 중 무료가 7,900명입니다. 무료 사용자의 인프라 비용은 월 1,400만원이고, 이 중 상위 5%가 비용의 62%를 씁니다. 무료→유료 전환율은 지난 12개월 평균 1.9%입니다.

축소하자는 근거: 상위 5%는 사실상 상용 서비스에 무료로 쓰고 있습니다.
반대 근거: 개발자 커뮤니티 유입 경로의 상당수가 "무료로 충분히 써봤다"는 후기입니다. 경쟁사 B는 월 5천 건을 제공합니다.

이번에 바꾸면 기존 사용자에게는 3개월 유예를 줘야 합니다.
```

**목표**
```
축소할지, 한다면 어느 선까지 할지, 기존 사용자 처리 방침까지 정하기
```

**라운드 수**: 2

**참여자**

| 이름 | 입장 | 아는 것 / 숨은 사정 |
| --- | --- | --- |
| 윤채린 (그로스) | 축소 반대 | 최근 유입 3건 중 1건이 특정 개발자 블로그 후기에서 왔다는 걸 확인함 |
| 조현우 (인프라) | 축소 찬성 | 상위 5% 중 절반이 같은 회사 도메인 계정이라는 걸 발견함 |
| 신예은 (CS) | 조건부 찬성 | 유예 3개월로는 문의가 폭주할 거라고 봄. 지난 정책 변경 때 경험 있음 |
| 남기훈 (재무) | 축소 찬성 | 다음 투자 라운드에서 무료 사용자 비용 구조를 지적받을 가능성을 우려 |

## 5. 채용 — 답이 이미 정해진 것처럼 보이지만 아닌 케이스

**주제**
```
시니어 백엔드 1명 vs 주니어 2명 채용
```

**배경**
```
다음 분기 채용 예산으로 시니어 1명(연봉 9천만원대) 또는 주니어 2명(각 4천5백만원대)을 뽑을 수 있습니다.

현재 백엔드는 4명이고 이 중 3년차 이상이 1명입니다. 코드 리뷰가 특정 1명에게 몰려 있고, 그 사람의 리뷰 대기 시간이 평균 1.8일입니다.

시니어를 뽑자는 쪽은 리뷰 병목과 아키텍처 결정을 들고, 주니어를 뽑자는 쪽은 반복 업무 처리량과 장기적 인력 구성을 듭니다. 지난 6개월간 시니어 채용을 시도했으나 최종 합격자 2명이 모두 오퍼를 거절했습니다(사유: 연봉, 스톡).
```

**목표**
```
어느 쪽으로 채용을 진행할지 정하고, 안 되는 경우의 대안까지 정하기
```

**라운드 수**: 2

**참여자**

| 이름 | 입장 | 아는 것 / 숨은 사정 |
| --- | --- | --- |
| 황준영 (리뷰 병목 당사자) | 시니어 | 본인이 병목인 걸 알지만 "내가 힘들다"고 말하기 껄끄러워함 |
| 배수정 (CTO) | 주니어 2명 | 시니어 오퍼 거절 사유가 연봉이 아니라 기술 스택이었다는 피드백을 받았음 |
| 노현서 (백엔드 1년차) | 시니어 | 배울 사람이 없어서 성장이 정체됐다고 느낌 |
| 권민지 (인사) | 판단 유보 | 현재 연봉 테이블로는 시니어 채용이 3개월 안에 될 확률이 낮다고 봄 |

## 자동 실행

시나리오를 골라 회의 생성 → 참여자 답변 → 마감 → 재질문까지 자동으로 돌립니다.
먼저 dev 서버를 띄운 뒤:

```bash
npm run seed 1
```

숫자는 시나리오 번호(1~5)입니다. 끝나면 주최자 화면 링크를 출력하므로,
브라우저로 열어 실제 정리 결과와 재질문을 확인하면 됩니다.

참여자 답변은 위 표의 입장에 맞춰 `samples/scenarios.mjs` 에 미리 적어둔 문구를 씁니다.
**AI 호출은 라운드당 2회(질문 생성 + 답변 정리)뿐입니다.** 참여자가 몇 명이든 늘지 않습니다.

답변까지 AI가 페르소나대로 쓰게 하려면 `--ai` 를 붙이세요. 더 현실적인 대신
호출이 참여자 수 × 라운드 수만큼 추가됩니다.

```bash
npm run seed 1 --ai
```

> `gemini-3.6-flash` 무료 한도는 **하루 20회**입니다. 여러 번 돌려볼 거면
> `.env.local` 에 `GEMINI_MODEL=gemini-flash-lite-latest` 를 넣으세요. 한도가 훨씬 넉넉합니다.
